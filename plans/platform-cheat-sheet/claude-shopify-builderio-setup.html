Shopify + Builder.io plugin + Claude Code

How to wire up the exact setup you proposed — Shopify as the managed platform, Builder.io as a visual plugin (not headless), and Claude Code just communicating with the store over the API.

Verdict: ✅ Real, viable, non-headless, and mostly no-code. The only things you truly own: keep the Shopify API token safe, approve Claude's write actions, and a one-time Builder theme block. Payments + card data stay sealed in Shopify throughout.
The shape of it

Three layers, one managed store

Nothing is headless. Shopify hosts and secures everything; the other two ride on top.

SHOPIFY

The platform. Hosts the store, runs commerce + checkout + payments, owns the secure vault (card data, customers). Fully managed — PCI/SSL/security done for you.

BUILDER.IO

Plugin / visual layer. A Shopify App-Store app that adds drag-and-drop sections into your existing theme. Reads public product data only. Never touches checkout.

CLAUDE CODE

Communicates. Talks to the store via Shopify's API (MCP) to read/edit products, inventory, discounts, run expiry reports — on your instruction. Hosts nothing.

Layer ① · the look

Set up Builder.io as a plugin non-headless

Visual sections that render inside your normal Shopify theme. Headless/Hydrogen is optional — you don't use it.

  1. Install the Builder.io app from the Shopify App Store (apps.shopify.com/builder-2).
  2. In Builder → Integrations → Shopify, paste a Storefront access token + your store domain (copy-paste from Shopify admin — no code).
  3. Build pages/sections in Builder's drag-and-drop editor.
  4. Add them to your theme — two options:
     • Online Store 2.0 theme → add Builder as a theme block in the customizer = zero code.
     • Older theme → paste a 1–2 line Liquid snippet like {% include 'model.x.builder' %} (guided copy-paste).

Code you own

  • Builder hosts & renders the section code (managed) — not you
  • With OS 2.0 themes: none at all
  • Older themes: one 1–2 line snippet, once

    Layer ② · the assistant

    Connect Claude Code to Shopify via MCP

    Shopify ships official MCP servers in 2026 — this is the supported way for an AI tool to talk to a store. One-time setup ≈ 30–45 min, no real coding.

    Dev MCP — safe, no token

  • Gives Claude Shopify's API docs + schema
  • Read-only, zero risk — so Claude writes correct API calls
  • Good to add first

    • Admin-API MCP — acts on the store

  • Read/edit products, orders, inventory, discounts, theme
  • Needs an Admin API token
  • This is the "communicates with my store" part
    1. In Shopify admin → Settings → Apps → Develop apps → Create app ("Claude Code"). Clickable, no code.
    2. Pick Admin API scopes — start read-only: read_products, read_orders, read_inventory.
    3. Install app → copy the Admin API token (shpat_…) — shown once. Store it in 1Password.
    4. Add the MCP server to Claude Code (token via env var, ideally injected with op run so it never hits disk): 
      {
  "mcpServers": {
    "shopify": {
      "command": "npx",
      "args": ["-y", "@shopify/dev-mcp@latest"],
      "env": {
        "SHOPIFY_ACCESS_TOKEN": "${SHOPIFY_ACCESS_TOKEN}",
        "SHOPIFY_DOMAIN": "your-store.myshopify.com"
      }
    }
  }
}
    5. Test read-only: "list my products", "what stock expires in 30 days", "orders last 7 days".
    6. Add write scopes later (write_products, write_inventory) only once you trust it.
    What it lets you do (non-headless, just API talk): bulk product/price edits · inventory + expiry reports/alerts · create discounts · order/customer summaries · small theme tweaks · automations — all in plain English, Claude using the API under the hood. No hosting, no headless.
    Guardrails

    Security — the few things that are actually on you

    Do

  • Keep the Admin API token in 1Password / env var (you already do this)
  • Start read-only; add write scopes only when confident
  • Ask Claude to preview before applying bulk/destructive changes
  • Test on a dev/staging store first
  • Keep checkout on Shopify (no custom card forms anywhere)

    • Don't

  • Commit the token to git or put it in front-end code
  • Grant write scopes before you've tested reads
  • Run a vague write prompt ("halve all prices") without a preview
  • Move checkout into Builder.io (keep it on Shopify)
    • Card data is never exposed. Shopify's API doesn't return card numbers (you'd see "Visa ending 1234", not the number) — payments stay in Shopify's PCI vault. So a leaked token risks store-data tampering, not a card-data breach. Builder.io (Storefront token) only reads public catalog data and can't reach checkout.
    Biggest practical risk: Claude's write actions hit the live store with no undo. Mitigate with: read-only first → previews → minimal scopes → a dev store for experiments.
