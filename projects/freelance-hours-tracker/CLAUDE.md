# Freelance Hours Tracker

Domain: Engineering

A macro-powered Excel workbook (`FreelanceHoursTracker.xlsm`) that works like a stopwatch for freelance work: Start/Stop buttons log sessions per client, pay is computed from per-client hourly rates, and one button exports a professional monthly timesheet PDF. Built 100% locally (PowerShell + Excel COM); no APIs, no runtime dependencies beyond desktop Excel.

## Daily use (the whole manual)

1. Open `FreelanceHoursTracker.xlsm` (macros must be enabled — on this machine they already are).
2. **Dashboard** → pick a Client, type what you're doing in Task, click **▶ Start**. The banner goes green and the elapsed clock ticks live.
3. Click **■ Stop & Log** when done — the session lands as one row in **Time Log** (date, client, task, start, end, hours, rate, € amount).
4. **Juggling jobs:** with the timer running, just pick the other client/task and hit **▶ Start** — it offers to log the current session and start the new one with zero gap. One active clock at a time, so no hour is ever double-billed.
5. **Monthly report:** Report sheet → **Export PDF** → a dialog asks which client (or All Clients) + month (+ whether to include € amounts) → a print-ready A4 PDF appears next to the workbook: `Timesheet_2026-07_PetCentre_RiccardoTedesco.pdf`.
6. **Rates:** Clients sheet — type the €/h rate next to each client (they ship blank). Add a client = type a new row; every dropdown updates automatically. A rate change only affects rows via the lookup formula — you can overtype a fixed rate on any individual log row.
7. **Summary** sheet: hours + earnings per client per month, with a chart.

## Safety properties (why it's trustworthy)

- **Crash-safe:** every Start/Stop/switch writes its state to hidden Settings cells and saves the file. If Excel or the PC dies mid-session, the next open offers: keep timing / stop & log now / discard.
- Closing with the timer running is safe — it asks, and "keep running" resumes on next open.
- Times are stored as full date+time, so sessions crossing midnight compute correctly.
- The log flags: >8h days (amber), midnight-crossing rows (red date), hour magnitudes (data bars).

## Known trade-offs (accepted by design)

- While the timer ticks, Excel's **Undo history is cleared every second** (VBA writes do that). Edit old log rows while the timer is stopped.
- **Manually added** Time Log rows (typing a forgotten session directly) need the Date/Hours/Rate/Amount formulas dragged down from the row above — the macro-written rows carry them automatically.
- Exact-minute billing (no rounding) per Riccardo's choice — a very short session can show 0.00 h.
- Requires a licensed desktop Excel. If Microsoft 365 lapses into reduced-functionality (view-only) mode, the tracker stops working until reactivated.
- Copies sent to another PC get Mark-of-the-Web: right-click file → Properties → Unblock, or add its folder as a Trusted Location.

## Rebuild / develop

- VBA source of truth lives in `src/vba/` (text, git-friendly). The workbook is generated by:
  `powershell -File build/build-workbook.ps1` — **refuses to overwrite an existing workbook** (it may hold logged hours!) unless `-Force`. Rebuilding with `-Force` produces a FRESH EMPTY tracker.
- End-to-end test (runs the real macros on a throwaway copy, 29 assertions):
  `powershell -File test/smoke-test.ps1`
- Gotchas encoded in the scripts (don't relearn them): Excel overrides time-only number formats when VBA writes datetimes; `Range.Value` returns Double (not Date) for `hh:mm`-formatted cells; PS 5.1 unrolls COM Ranges returned from functions; inbound COM calls are rejected while the OnTime tick runs (retry); `VBComponents.Import` of a .cls would create `ThisWorkbook1` (use `AddFromString`); Form-control-style shape buttons, not ActiveX.
